# 全书语义分块质量评估 v0.1

## 结论

当前 `full-book-v0.1` 语义分块包可以作为知识图谱抽取的上层语义上下文和证据回溯索引，完整性与主题边界质量通过；但不应把 manifest 中的全部 section 不加区分地直接送入抽取模型。

`full-book-v0.1` 综合评级：**B+，有条件通过**。

- 来源完整性：A。全文无丢失、无重叠、无乱序，所有 section 均可回放到 canonical EvidenceChunk。
- 语义边界：A-。抽样未发现相邻医学项目被错误合并，跨页句子和同一项目的参考区间、异常解读能够保留在同一 section。
- 抽取就绪度：B。标题块、交叉引用、索引和重复页眉尚未显式标注为不同输入角色。

这不是实体/关系/规则抽取效果评测，也不使用抽取结果反推分块质量。后续抽取实验应单独进行。

## v0.2 整改结果

上述输入角色问题已在 `source-packages/derived/semantic-sections/full-book-v0.2` 中处理：

| content role | 数量 | 常规图抽取 | 路由 |
|---|---:|---|---|
| clinical_content | 256 | 是 | entity_relation_rule |
| introduction | 43 | 是 | entity_and_conservative_relation |
| cross_reference | 4 | 否 | cross_reference_resolution |
| index | 7 | 否 | alias_dictionary |
| structural | 21 | 否 | metadata_only |

- manifest 新增 `content_role`、`extraction_eligible` 和 `extraction_route`。
- 每个 section 新增等长的 `input_view_file`，只对重复页眉做空格掩码，字符坐标不移动。
- manifest 新增 `noise_spans`，记录噪声类型、section 坐标和原文哈希。
- 全书识别到 87 个含页眉噪声的 section，共 90 个 `running_header` span。
- 原始 `section_file`、canonical EvidenceChunk 和全部 source span 保持不变。

整改后的工程可用性评级为 **A-**。尚未给 A 的唯一原因是没有人工分块边界金标；这不再是已知的输入角色缺陷。

## 评估对象

- 语义包：`source-packages/derived/semantic-sections/full-book-v0.1`
- 来源包：`source-packages/canonical/evidence/full-book-v0.2`
- 来源规模：218 页、373 个 canonical chunk、152,133 字符
- 输出规模：331 个 section，其中 310 个语义内容块、21 个纯结构标题块
- 分块配置：目标 2,400 字符，上限 4,000 字符

## 检查方法

1. 对 331 个 section 做全量哈希与证据坐标回放。
2. 按 canonical chunk 检查所有来源区间，确认没有缺口或重叠。
3. 检查长度分布、跨页情况、过短块、强制拆分和结构块。
4. 分层定向抽查 34 个代表 section 及相邻边界，覆盖普通项目、长块、跨页块、短块、标题块、交叉引用和附录索引。

本轮没有人工标注的“理想分块边界”金标，因此不报告伪造的边界 Precision、Recall 或 F1。

- 61 个 section 少于 200 字符。它们多数是合理的教材层级节点，但不是同一种抽取输入。

## 抽样观察

抽查覆盖血液、肝肾功能、胃功能、心肌标志物、微量元素、肿瘤标志物、体液检验和附录。

表现良好的地方：

- “红细胞和血红蛋白”“白细胞分类计数”“幽门螺杆菌检测”等长项目保持为单一主题，参考区间、异常结果和解释没有被页边界拆散。
- “血浆凝血酶原时间”“血清尿素”“乳酸脱氢酶”等相邻项目边界与教材小节标题一致。
- 跨页断句仍保留在同一 section。例如幽门螺杆菌呼气试验跨页后的“内进行”没有被分到另一个医学项目。
- “心肌酶标志物检验 / 天冬氨酸转氨酶”“微量元素 / 铁”“尿酮体”等短交叉引用没有被错误并入后续项目。

未发现的严重问题：

- 未发现正文字符丢失或重复覆盖。
- 未发现不同检验项目因跨页而错误拼接。
- 未发现普通临床正文在句中被 4,000 字符上限截断。

## v0.1 发现的问题（v0.2 已处理）

### 1. 结构标题块不能作为普通抽取块

21 个 `kind=structural` section 只包含“出血和血栓检验”“肾小球滤过功能试验”等标题。它们适合维护层级路径，不适合单独调用实体关系抽取。

v0.2 处理：已设置 `extraction_eligible=false` 和 `extraction_route=metadata_only`。

### 2. 索引不应与临床正文使用同一抽取策略

“附录三 索引”被识别为 7 个普通 semantic part。索引适合抽取缩写、别名和术语映射，但不适合抽取疾病因果关系或临床规则。

v0.2 处理：已增加 `content_role=index`，路由到 `alias_dictionary`，并从常规图抽取中排除。

### 3. 章节引言和交叉引用需要显式类型

12 个不足 100 字符的语义块主要是章节引言或“见第二章”“见第六章”式引用。它们不是错误分块，但信息密度和抽取目标不同。

v0.2 处理：已增加相应 `content_role`；交叉引用路由到 `cross_reference_resolution`。

### 4. 页眉噪声仍保留在正文中

80 个 section 含有形如“第一章 临床血液检验”的裸章节行，其中既有章节引言，也有跨页重复页眉。保留它们有利于原文回放，但直接送入模型可能产生重复章节实体或干扰句法。

v0.2 处理：已增加等长输入视图和 `running_header` 噪声坐标，同时保留原始 source span。

## 使用建议

当前包可以直接用于：

- 数据回溯和循证定位；
- 为 canonical EvidenceChunk 提供章节路径和跨页语义上下文；
- 构建后续抽取实验的稳定输入视图。

进入全书抽取前，应先建立输入路由：

| content role | 处理方式 |
|---|---|
| clinical_content | 实体、关系、规则抽取 |
| structural | 仅作为层级元数据 |
| introduction | 可抽实体，谨慎抽关系 |
| cross_reference | 解析章节链接，不抽临床事实 |
| index | 只抽缩写和别名 |

最终建议：保留现有 canonical chunk 作为证据真值；使用 v0.2 语义 section 作为可路由的上层输入单元，再由专门实验评估实体、关系和规则抽取效果。
